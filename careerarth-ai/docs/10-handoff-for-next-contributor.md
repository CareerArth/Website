# 10 — Handoff for the Next Contributor

If you're picking this project up — as a new team member, a future course team, or
just future-you after a break — this is the orientation document. It points into the
existing, fairly extensive doc set rather than repeating it; read this first, then
follow the links for depth.

## What this is, in 30 seconds

A prototype AI-assisted career diagnostic for CareerArth: a user answers a structured
20-item questionnaire, gets a deterministic score across four dimensions (**A**lignment,
**R**isk Exposure, **T**rajectory, **H**uman Capital), then an AI-drafted, evidence-cited
analysis of their situation, reviewed by a human consultant before anything is final.
It lives entirely inside `careerarth-ai/` and never touches the production CareerArth
site (`app/`, `components/`, `lib/`, `aws/` at the repo root).

## Run it

```bash
cd careerarth-ai
npm install
npm test          # 42 tests, no API key, no network
npm run demo       # runs 6 synthetic personas through the pipeline (mock mode)
npm start          # http://localhost:4747
```

Screens: `/` (intake), `/report/:id` (customer report), `/review/:id` (consultant
review), `/runs` (index of all runs), `/admin` (edit scoring weights). None are
authenticated — this is a prototype, not a deployable product; see Limitations below
before putting a link to any of these in front of a real user.

## Evidence status (condensed from `docs/stage4`)

**Demonstrated:** the full pipeline runs end-to-end and is tested (42/42 automated
tests); scoring is deterministic and config-driven; 6 synthetic personas produce
meaningfully different, internally consistent results.

**Implemented but never exercised live:** the real Claude API integration
(`src/report/generate.ts`) — every report ever generated by this project, including all
demo personas, used the deterministic mock generator, because no `ANTHROPIC_API_KEY`
has been configured. Nobody has read a real AI-generated report from this system.

**Pure hypothesis, no evidence:** the target customer segment, willingness to pay,
conversion from free diagnostic to paid consultation, and the specific pricing figures
in `docs/stage3`. A pilot protocol exists (`docs/stage4/04-pilot-protocol.md`,
`05-research-materials.md`) but has not been run.

Treat any claim not explicitly labeled otherwise with that framing.

## How to extend this — the parts this handoff specifically unlocks

**Add a new scoring modifier condition** (not just adjust an existing one's size/delta —
the admin dashboard already covers that): add an entry to the `modifiers` array in
`context/scoring-config.json` (id, dimension, delta, active — the `when` field is just
descriptive text, not parsed), then add a matching `case` to the `switch` statement in
`activeModifiers()` in `src/scoring/score.ts`. Config and code must agree; there's no
way to add a genuinely new condition through config alone.

**Fully migrate to a native 1–5 (or other) stored answer scale** instead of the current
0–4-with-UI-mapping approach: change `answerScale` in `context/scoring-config.json`,
the hardcoded `z.number().int().min(0).max(4)` in `questionnaireSchema` (`src/types.ts`),
the matching `minimum`/`maximum` in `context/profile.schema.json`, and remove the
UI-side mapping in `web/intake.js`'s `renderLikert()`. Not done as part of this handoff
because it touches validation and schema, not just config — see
`docs/09-admin-dashboard-and-new-questionnaire.md` for why the simpler UI-mapping
approach was chosen instead.

**Add authentication** before `/admin` or `/review/:id` are exposed beyond a local
demo — neither has any auth today, by design (matches the rest of this prototype), but
either would need it before being shared with anyone who shouldn't be able to edit live
scores or approve reports.

**Wire up the live Claude API**: set `ANTHROPIC_API_KEY`, then `npm run demo` — the
integration is fully written (`src/report/generate.ts`), just never exercised. Read the
resulting reports carefully before trusting them for a demo; the mock generator's output
has been the only thing anyone has actually reviewed so far.

**Run the Stage 4 validation pilot**: the protocol, recruitment message, consent text,
surveys, and success/failure thresholds are all written and ready
(`docs/stage4/04-pilot-protocol.md`, `05-research-materials.md`) — this is the single
highest-leverage next step for anyone continuing the *business* side of this project,
since almost nothing about real customer demand has been tested yet.

## Known limitations (unchanged by this handoff, still true)

Single-process, file-backed storage (`data/`, gitignored); no authentication anywhere;
no payment or booking flow (the consultation CTA records interest, nothing more); the
ARTH rubric weights are heuristic, calibrated to reproduce one published example score,
not validated against real outcomes; the 18-role knowledge base covers only
technology/finance/marketing — profiles outside that get a degraded, honestly-flagged
experience. Full list: `docs/08-mvp-implementation.md` and `docs/stage4/01-evidence-audit.md`.
